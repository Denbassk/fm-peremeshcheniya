## 2. Где логика смешана с интерфейсом

Хорошая новость: тяжёлая логика уже вынесена из окна. `run_vyvoz`, `run_split`, `run_update`, `run_final_inventory`, `scan_stores`, `input_status`, `file_state`, `list_corrected`, `auto_lists`, `corrected_check` не зависят от tkinter. В модуле нет импорта tkinter на верхнем уровне, только внутри функций окна. Значит, `vyvoz_vne_matricy.py` можно оставить «ядром» без Qt и подключать его из GUI.

Внутри обработчиков окна осталась логика, которую нужно вынести в ядро **до** переноса. Иначе её придётся переписывать дважды.

| # | Место | Что смешано | Куда вынести |
|---|---|---|---|
| L1 | `run_bg` (6569) | Вывод функций ловится через `contextlib.redirect_stdout` в фоновом потоке. Это подмена глобального `sys.stdout`: всё, что напечатает главный поток в это время, тоже попадёт в журнал задачи. Ошибки читаются из глобального `R.checks` | Функция-обёртка в ядре возвращает `(результат, текст_лога)` и принимает callback для строк. В Qt это сигнал `log_line(str)` от QThread-воркера |
| L2 | `on_mode` / `mode_refresh` (6786, 6820) | Один режим превращается в два флага (`manual`, `sweep`). Тексты «что не вывозим» в каждом режиме повторяют бизнес-правила прямо в окне | `VyvozOptions` (режим, rm, поставщики) и `mode_description(options, n_sup)` в ядре |
| L3 | `go().done` (6885) | Окно само собирает путь к результату: `day_dir/имя/имя.xlsx` с `rz.safe_name` | `run_vyvoz` возвращает путь листа в `info["shops"][i]["list"]` |
| L4 | `refresh().done` (6862) | Окно отсеивает Полевую (`_is_polevaya`) и собирает ошибки из `R.checks` | `scan_stores` сразу без складов; ошибки в результате функции |
| L5 | `raw_list_ok` (6926) | Окно решает, что лист «автоматический», проверяя, лежит ли путь внутри `dirs.out` | `is_auto_list(dirs, path)` в ядре; в окне только вопрос |
| L6 | `split_go` (7057) | Проверка входа по цепочке: файл есть, из «Корректировка_ЮА», `corrected_check`, `_clamp_top` | `validate_split_input(dirs, path, n)` возвращает текст ошибки или None |
| L7 | Список «один магазин» (7037) | Варианты берутся из `rz.ROUTES`, а `run_split` принимает только работающие точки: без источника и без магазинов ЮА. В списке есть имена, которые потом дадут ошибку. Поле редактируемое, можно ввести опечатку | `split_targets(dirs, path)`: ровно тот список, что примет `run_split` |
| L8 | `open_split_xlsx`, `open_final_xlsx` (7043, 7188) | Окно угадывает имя файла: «Распределение.xlsx», или «первый xlsx в папке» | Функции возвращают точный путь в `info` |
| L9 | Форматирование чисел | `"{:,.0f}".format(...).replace(",", " ")` повторяется в 4 местах | Общий `fmt_money()`, `fmt_qty()` |
| L10 | `open_suppliers_dialog` | Внутри диалога и чтение `known_suppliers`, и запись CSV | Диалог только показывает список; сохранение через функцию ядра |
| L11 | `TITLES` и подсказки | Правила работы («на следующий день сюда не возвращайтесь») записаны только серым текстом в окне | Словарь текстов отдельно; в Qt это tooltip, кнопка «?» и раздел справки |

Самотест: `_selftest_window` и проверки диалога поставщиков (2444–2470, 2801–2810) создают окна tkinter. Их нужно переписать на Qt с `QT_QPA_PLATFORM=offscreen` на том же шаге, где переносится экран.

## 3. Проблемы UX уже сейчас (аудит по qt-ui-design)

### Critical
1. **«Весь вывоз на один магазин» не найти.** Поле лежит на экране 2, в карточке параметров, четвёртой строкой. Это редактируемый список с длинной серой подсказкой. Кроме того, оно спорит с двумя другими настройками: при выбранном магазине «число точек» и «подобрать по сумме» молча не действуют, хотя остаются активными. Нужен один выбор «Как делить»: по N точкам / подобрать по сумме / всё на один магазин. Список магазинов появляется только в третьем варианте и содержит только допустимые имена (L7).
2. **Выделение красным = ошибка красным.** Выделенная строка таблицы закрашивается фирменным красным (`Treeview selected = FM_RED`), и ошибки тоже красные. На скриншоте выбранный магазин выглядит как ошибка. Выделение нужно сделать нейтральным: светлая подложка, тёмный текст, красная полоса слева. Красный оставить для ошибок и одной главной кнопки.
3. **Состояние передаётся только цветом.** Статусы выгрузок (зелёный / жёлтый / красный) и подсказка режима (зелёный текст) различаются только цветом текста. Нужны значок и слово: «Свежая», «Старая, 47 ч», «Нет файла».
4. **Клавиатура.** Пункты бокового меню — это `tk.Label` с обработчиком щелчка, на них нельзя попасть по Tab. Колесо мыши перехвачено глобально (`bind_all`). В Qt меню — это кнопки или QListWidget с фокусом и стрелками.
5. **Контраст (WCAG, нужно ≥ 4.5:1 для мелкого текста):**

   | Элемент | Контраст |
   |---|---|
   | «ПОРЯДОК РАБОТЫ» на боковой панели | 2.83 |
   | Путь «Данные:» внизу панели | 2.88 |
   | Зелёный текст режима | 3.05 |
   | Жёлтый текст | 2.95 |
   | Красный #E31E24 текстом на тёмной панели | 2.97 |
   | Серые подсказки на фоне | 4.48 |
   | Белый на красной кнопке | 4.69, проходит |

### Warning
6. **Порядок шагов нарушен.** Шаг 3 и главная кнопка закреплены внизу. Шаги 1 и 2 прокручиваются над ними, между ними пустая таблица результата. На скриншоте шаг 1 уехал вверх, видны две полосы прокрутки: страницы и таблицы. Таблица магазинов высотой в 2 строки.
7. **Названия не совпадают.** В подзаголовке «нажмите «Сформировать списки вывоза»», на кнопке «Сформировать список», в меню «Списки вывоза». Пункт «3 Подчистка списка» — это действие следующего дня, а не третий шаг подряд; нумерация 1–4 обещает последовательность, которой нет.
8. **Серые абзацы на каждом экране:** подзаголовок страницы, подсказки под каждой карточкой, пояснение режима, пояснение поставщиков. По правилам проекта длинные пояснения уходят в tooltip или кнопку «?».
9. **Настройки режима спрятаны, но пересказаны.** Галочка «Вывозить и товар из матрицы…» свёрнута в «Настройки ▾», а её действие написано в строке режима. Пользователь видит следствие, но не видит переключатель.
10. **Кнопки без результата активны.** «Папка результата», «Сводка (Excel)», «Распределение (Excel)» и другие активны до расчёта и отвечают окном «Нет результата». Их нужно выключать, пока результата нет.
11. **Обрезанный текст.** «Вывоз вне матрицы · переход на К» обрезан в боковой панели.
12. **Ширина подсказок задана один раз.** `wraplength=W - px(320)` считается при старте и не меняется при изменении размера окна.
13. **Шрифты.** Размеры 17, 10 bold, 10, 9, 8 пунктов — больше трёх-четырёх на экран. Основной текст 10 pt (около 13 px) мельче нормы qt-ui-design (16 px).
14. **Нет тёмной темы** (обязательна по правилам проекта).
15. **Свободный ввод там, где нужен выбор:** магазин на экранах 2 и 4 можно вписать с опечаткой.
16. **Ошибки видны только в «Журнале».** Пользователь должен переключиться туда сам.
17. **Экран 2: два источника листа рядом.** Список из «Корректировка_ЮА» и «автоматический» с «Взять без правок» легко перепутать.

### Opportunity
18. Плашка результата на месте («Готово: 2 магазина, 148 позиций, 31 500 грн · Открыть · Журнал») вместо статуса внизу окна.
19. Прогресс по этапам (чтение выгрузок → BigQuery → Excel) вместо бесконечной полосы. Операции с BigQuery идут дольше 10 секунд, а скилл требует показывать этап.
20. Выбранный магазин и свежесть его выгрузки показывать карточкой над кнопкой, а не отдельной зелёной строкой.
21. Экран 2: после расчёта в режиме «один магазин» показывать оценку продаж за 60 дней прямо в окне, а не только в Excel.

## 4. Дизайн-система под Фемелі Маркет

**Токены.** В `design_tokens.md` в `main` сейчас стоит «Corporate Blue» (#003d9b). Фирменного акцента #E31E24 и тёмной боковой панели там пока нет. Если вы внесли их у себя, отправьте в репозиторий. Если нет, это первый шаг PR 1. Предлагаю сопоставить так:

| Токен | Значение | Откуда |
|---|---|---|
| `COLOR_PRIMARY` | `#E31E24` | `FM_RED` в коде |
| `COLOR_PRIMARY_PRESSED` | `#B8161B` | `FM_RED_D` |
| `COLOR_PRIMARY_CONTAINER` | светлая красная подложка для выделения, тёмный текст | подобрать с контрастом ≥ 4.5 |
| `SIDEBAR_BG` | `#2B2C30` | `FM_GRAPH`, одинаков в светлой и тёмной теме |
| `SIDEBAR_HOVER` | `#34353A` | из кода |
| `SIDEBAR_ACTIVE` | `#3D3E44` | из кода, плюс красная полоса 3 px слева |
| `SIDEBAR_TEXT` | `#B4B4BA` (6.76) | из кода |
| `SIDEBAR_MUTED` | заменить `#6F7077` | нужен контраст ≥ 4.5 |
| `COLOR_ERROR` | **другой** красный, не #E31E24, всегда со значком | разделить «бренд» и «ошибку» |
| `DARK_PRIMARY` | осветлённый красный для текста и рамок на тёмном фоне | #E31E24 на тёмном даёт 2.97 |

Красный текстом на тёмной панели использовать нельзя: 2.97. На панели красной остаётся только полоса активного пункта, а надпись «ФЕМЕЛІ МАРКЕТ» в логотипе — крупный текст, для него хватает 3:1.

**Шрифты Inter и Hanken Grotesk** — файлы .ttf в проекте, встраиваются в exe:
- Положить в `Перемещения ЮА/assets/fonts/`: `Inter` (Regular, Medium, SemiBold), `HankenGrotesk-SemiBold.ttf` и их `OFL.txt`. Обе гарнитуры под лицензией OFL, её текст положить рядом.
- **Проверить кириллицу Hanken Grotesk**, в том числе украинские і, ї, є, ґ: логотип «ФЕМЕЛІ МАРКЕТ», имена магазинов. Я не уверен, что в ней есть полная кириллица. Проверка простая: `QFontDatabase.writingSystems("Hanken Grotesk")` содержит `Cyrillic`. Если нет, заголовки делаем Inter SemiBold. Это вопрос к вам, см. раздел 6.
- Загрузка через `QFontDatabase.addApplicationFont`. Путь определять так: `getattr(sys, "_MEIPASS", os.path.dirname(os.path.abspath(__file__)))`. Шаблон из скилла с `Path(__file__).parent` в onedir-сборке указывает в `vyvoz_lib`, и это работает только потому, что туда же ляжут datas. Надёжнее явно через `_MEIPASS`.
- Если шрифт не загрузился, работаем на Segoe UI и пишем в журнал. Так уже сделано для иконки окна (`_fm_icon_err`).
- Размеры задавать в пунктах (`pointSize`), чтобы работало масштабирование Windows 125–150 %. Ручной пересчёт `px(v)` и вызов `SetProcessDpiAwareness` в Qt 6 не нужны: Qt масштабирует сам.

**Иконки Material Symbols** — встроенным шрифтом:
- `MaterialSymbolsOutlined[FILL,GRAD,opsz,wght].ttf` (Apache 2.0) в ту же папку. Файл вариативный и крупный, около 10 МБ. Если размер exe важен, можно урезать до нужных символов через `pyftsubset` из fonttools.
- Иконки задавать кодом символа (`""`), а не названием-лигатурой. Словарь `ICONS = {"folder": "", ...}` держать рядом с токенами.
- Кнопки только с иконкой получают tooltip и `accessibleName`.

**PyInstaller** (`vyvoz_vne_matricy.spec`):
- `datas += [("assets/fonts", "assets/fonts")]`.
- Убрать из `hiddenimports` строки `tkinter`, `tkinter.ttk`, когда окно tkinter будет удалено.
- Добавить в `excludes` неиспользуемые части Qt: `PySide6.QtWebEngineCore`, `QtWebEngineWidgets`, `Qt3D*`, `QtQuick*`, `QtMultimedia`, `QtCharts`. Без этого сборка вырастет на сотни мегабайт.
- `contents_directory="vyvoz_lib"` оставить, `install_vyvoz.bat` не менять.

## 5. Порядок переноса (один экран — один PR)

Пока идёт перенос, у программы два окна. Ключ `--tk` запускает старое, по умолчанию открывается новое, как только в нём есть экран 1. Если Qt не стартовал, программа сама открывает tkinter и пишет причину. Старое окно удаляется последним PR.

|---|---|---|

## 6. Решения владельца (14.10.2026)

1. **Токены.** Своей версии нет. Токены записаны по таблице раздела 4 прямо в нашу копию скилла:
   `.claude/skills/pyqt6-ui-designer/references/design_tokens.md`. Там же поправлены
   `qss_patterns.md` и `component_library.md`. Красный `#E31E24` только у кнопки действия
   и у полоски активного пункта. Выделение строк, галочки, фокус и прогресс нейтральные.
   Панель тёмная.
2. **Hanken Grotesk проверен через fontTools** (версия 3.013 из google/fonts): кириллицы нет
   совсем, ни А–я, ни і ї є ґ І Ї Є Ґ. **Заголовки тоже Inter.** В Inter 4.001 кириллица полная,
   украинские буквы есть.
3. **Основной текст 14 px.** Окно обязано правильно масштабироваться при 125 % и 150 % в Windows.
   В облаке проверка через `QT_SCALE_FACTOR=1.25` и `1.5` со скриншотами, на Windows — вручную.
4. **Номеров в меню нет.** Меню по группам:
