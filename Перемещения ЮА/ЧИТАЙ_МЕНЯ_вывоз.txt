ВЫВОЗ ВНЕ МАТРИЦЫ - vyvoz_vne_matricy.exe (или vyvoz_vne_matricy.py)
======================================================================

Зачем. Магазины переходят на ЮА Маркет, через него заказывается только действующая
матрица. Программа делит остаток магазина (Family) на: что вывезти на Полевая-Склад
(Family), что остаётся на полке и переводится на ЮА инвентаризацией, что не трогаем.
Выдаёт xlsx для печати и txt для ТСД. Обратно в магазины ничего не раздаёт.
Расчёт заказа (raschet_zakaza) не затрагивает.

КУДА КЛАСТЬ ВЫГРУЗКИ ТОРГСОФТА
(папка «Перемещения ЮА\ВХОД_ВЫВОЗ» рядом с папкой программы; результат «Перемещения ЮА\ВЫВОЗ»,
кэш и логи там же; другое место - переменная FM_VYVOZ_DIR. Если папки «Перемещения ЮА» нет,
всё лежит рядом с программой. Ключ BigQuery берётся из credentials рядом с программой.)
  МАГАЗИНЫ\      «Состояние склада» каждого магазина, база FAMILY (не ЮА). Один файл на магазин.
                 Нулевые и минусовые строки допустимы: программа берёт только остаток > 0.
  СКЛАД_ЮА\      «Состояние склада Полевая-Склад ЮА», ВСЕ строки, в том числе с нулём
                 («заведён на ЮА» не значит «есть сейчас»). Нужен самый свежий файл (один).
  ПРИХОДЫ_ЮА\    «Приходы» ЮА (Движение товара) ЗА ВЕСЬ ПЕРИОД с первой поставки на склад ЮА,
                 все типы документов. По нему видно, откуда на складе ЮА каждый товар.
  МАГАЗИНЫ_ЮА\   не обязательно, после перехода магазина: «Состояние склада» магазина в базе ЮА.
                 Это номенклатура магазина (любой остаток, в т.ч. 0 и минус - товар в пути). На магазин влияет только
                 ЕГО выгрузка (по имени, «Болградська 38 ЮА» = Грозненська 38); выгрузки других магазинов не учитываются.
  БАЗА_ЮА\       не обязательно, но желательно: «Состояние склада» ВСЕХ товаров по ВСЕМ точкам ЮА (с 09.10.2026).
                 Карточка в базе ЮА, даже с нулём или минусом, = товар на ЮА заведён. Берётся самый свежий файл
                 (дата в имени: «База ЮА 09.10.2026.xlsx»). Обновляйте перед каждым переходом магазина.
  Что и откуда подгружать - видно в окне: «Списки вывоза», шаг 1 показывает по каждой папке файл, время выгрузки и статус
  (свежая / СТАРАЯ, старше суток / НЕТ ФАЙЛА); «×N» - сколько файлов в папке. Склад ЮА выгружайте со ВСЕМИ строками.
Матрица берётся из листа Google «Ассортиментная матрица (полная)» (свежее: в BigQuery её заливают раз в день);
если лист недоступен - из BigQuery (assortment_matrix_full). Чем они отличаются, видно в логе. Перекодировка ШК,
сырьё кофеаппарата, история поставок и последний поставщик берутся из BigQuery сами (кэш в Справочник\vyvoz_*.csv).
Продажи программа не использует.

ОКНО (PySide6, по умолчанию)
  Двойной щелчок по vyvoz_vne_matricy.exe открывает новое окно; прежнее окно - ключ --tk. Меню по группам: Сегодня
  (Списки вывоза, Распределение, Сверка накладной), Отдельно (Инвентаризация ЮА). Пояснения -
  кнопка «?» рядом с текстом. Распределение: один выбор «Как делить» - по N точкам / подобрать число точек по сумме /
  всё на один магазин (в списке только магазины, которые распределение примет). Сервис -> Оформление: тема (Светлая /
  Тёмная / Как в Windows) и шрифт (Inter / Segoe UI), выбор запоминается; какой шрифт окно рисует на самом деле, пишется
  в «Журнал». Горячие клавиши: Ctrl+1...Ctrl+6 - разделы, F5 - «Перечитать». Не открылось новое окно - программа
  пишет причину и открывает прежнее. Описание ниже - по прежнему окну (--tk), действия в новом те же.

КАК ЗАПУСТИТЬ
  Двойной щелчок: окно с разделами 1 Списки вывоза, 2 Распределение, 3 Инвентаризация ЮА, Сервис,
  Журнал. «Списки вывоза» - три шага на одной странице:
    Шаг 1. Проверьте выгрузки: что лежит в каждой входной папке, какой файл взят, когда выгружен, свежий ли
           (двойной щелчок - открыть папку). Положили новые файлы - «Перечитать».
    Шаг 2. Выберите магазин: по умолчанию выбран один - тот, чью выгрузку сняли последней (дата в имени файла, затем
           время файла); «Будет сформирован список для: ...» под таблицей. Нужен другой - щёлкните по нему (Ctrl/Shift -
           несколько, программа переспросит). «Скрыть магазин» прячет его из таблицы: файлы выгрузок не трогаются и не
           удаляются, «Показать скрытые» возвращает (список скрытых - Справочник\vyvoz_hidden_stores.csv).
    Шаг 3. Как составлять список: строка с режимом закреплена внизу страницы рядом с кнопкой «Сформировать список»
           (всегда видно, что будет сделано); режим выбирается переключателем: Обычный / РУЧНОЙ ВЫБОР (по умолчанию) и галочкой «Вывезти ВСЁ»;
           «Настройки» открывают:
           зачистка остатка, поставщики, список ШК.
  У каждой кнопки название по действию («Открыть папку результата», «Перечитать», «Взять без правок»), у каждого
  раздела вверху страницы написано, что он делает.
  Без окна:  vyvoz_vne_matricy.py --shops "Качанівська 19;Грозненська 38" --remove-not-on-ua
             или --auto (все магазины). Проверка кода: vyvoz_vne_matricy.py --selftest
             --manual - ручной выбор (см. ниже).
  Окно: галочка «Убирать и то, что в матрице, но на ЮА не завозилось» (включена по умолчанию) = ключ --remove-not-on-ua.
  Кнопка «Поставщики: кого не вывозить...» - выбор поставщиков (см. ниже); рядом видно, сколько поставщиков в списке и когда он сохранён.
Полевая в вывоз не берётся никогда. Перед запуском закройте в Excel файлы прошлого вывоза.

ЧТО ПОЛУЧАЕТСЯ (ВЫВОЗ\<дата>\)
  <магазин>\<магазин>.xlsx   листы:
     Вывезти на склад              сбор товара (по поставщику), сюда же печатать
     Нет в матрице (весь список)   все позиции остатка, которых нет в матрице, и что с ними решено
     Остаётся - инвентаризация ЮА  что остаётся на полке; колонка «ШК в файле для ЮА»
     Нет в матрице, но есть на ЮА  ЮА этот товар уже закупал, а в матрице его нет (ждёт решения)
     В матрице, на ЮА не было      в матрице, но на ЮА ни разу не приходил; по поставщику
     По поставщикам                те же позиции по поставщикам: для закупщицы (прямая/РЦ/без поставок)
     Исключено (не трогаем)        стаканы, пакеты, сырьё кофеаппарата, сигареты, кулинария, овощи на развес,
                                   исключённые поставщики и т.п., причина в колонке
     Штучные - упаковка на ЮА      штучный товар («... 1 шт»), чья упаковка уже есть на ЮА под другим ШК: не вывозим
     Один товар, разные ШК         то же название под разными ШК (матрица/ЮА)
     Сигареты - возможные пары     сигареты Family (кириллица) и ЮА (латиница): пары и статус
  <магазин>\<магазин>.txt    вывоз для ТСД, ШК;количество (cp1251, \r\n), после записи перечитан и сверен
  <магазин>\<магазин>_инвентаризация_ЮА.txt   то, что остаётся на полке; ШК - тот, что знает ЮА
  _СВОДКА_ВЫВОЗ.xlsx         На склад, По магазинам, те же листы по всем магазинам, Проверки
  В «Проверках» баланс остатка: вывезти + перевести на ЮА + ждёт решения + кулинария = весь остаток.

РУЧНОЙ ВЫБОР (галочка в окне, по умолчанию включена; в командной строке --manual)
  В лист «Вывезти на склад» добавляются сигареты и кеги, которых правила ниже обычно не вывозят (решение 08.10: «сигареты
  вывозим, кег вывозим») - кроме тех, чей поставщик отмечен «не вывозить» или ШК в списке «не вывозить». ГАЛОЧКИ ПОСТАВЩИКОВ
  И СПИСОК ШК ДЕЙСТВУЮТ ВСЕГДА: товар поставщика с галочкой в список не попадает. Пакеты, стаканы и расходники, сырьё
  кофеаппарата, овощи, кулинария и выпечка в список не попадают, как в обычном расчёте.
  Прежняя причина - в последней колонке «Обычно не вывозим (причина)», в A3 красная пометка. Лишние строки удаляете вы
  в Excel (удобен фильтр по последней колонке), лист сохраняете в «Корректировка_ЮА». Файл txt рядом собран до вашей правки:
  после удаления строк он не совпадает с листом. «Ждёт решения» и «Штучные - упаковка на ЮА» - отдельные листы решений,
  режим их не меняет. С зачисткой остатка не сочетается (в окне при зачистке он выключается).

ВЫВЕЗТИ ВСЁ, КРОМЕ ТОГО, ЧТО СТОИТ У МАГАЗИНА НА ЮА (галочка в шаге 3; в командной строке --all-out; решение 22.10.2026)
  Не режим, а галочка поверх выбранного режима: переключатель режимов и «вывозить и товар из матрицы» при ней отключены.
  Правил нет вовсе: уезжает ВЕСЬ остаток - и то, что в матрице и заведено на ЮА где-то ещё, и сигареты, кеги, пакеты, стаканы,
  сырьё кофеаппарата, овощи, кулинария, штучные, поставщики с галочкой и список ШК «не вывозить». На месте остаётся ТОЛЬКО то,
  что стоит у ЭТОГО магазина на ЮА: в «Приходах» строки с получателем «<магазин> ЮА» ИЛИ остаток этого магазина в выгрузке
  МАГАЗИНЫ_ЮА больше нуля (по ШК, склейке / перекодировке или названию). Это пересечение «есть у Фемели и уже стоит у этого
  магазина на ЮА»; оно идёт на лист «Остаётся - инвентаризация ЮА» и в txt инвентаризации. Обычный расчёт смотрит на ЮА
  вообще (склад, приходы любых точек, база), поэтому товар, заведённый на ЮА где-то ещё, но не у этого магазина, в обычных
  режимах остаётся на полке - отсюда остатки, которые не уезжали (Ньютона 111, 21-22.10.2026).
  НАДПИСЬ ПОСЛЕ ПРОВЕРКИ: после формирования программа независимо перечитывает готовые файлы (лист и txt) и сверяет КАЖДЫЙ ШК и
  количество с исходной выгрузкой магазина. Сошлось - в окне, в «Проверках» и в итоге: «ПРОВЕРКА ПРОЙДЕНА: ВЕСЬ ОСТАТОК БУДЕТ
  ВЫВЕЗЕН» (или «ВЕСЬ ОСТАТОК, КРОМЕ N ПОЗ., БУДЕТ ВЫВЕЗЕН» с разбивкой: вывезти / остаётся на ЮА / ШК не загрузить). Не сошлось -
  «ПРОВЕРКА НЕ ПРОЙДЕНА» с причиной (ШК пропал, лишний, другое количество), по магазину ОШИБКА, файлы брать нельзя.
  Единственное исключение из «всё»: ШК не из 6-14 цифр (в ТСД не загрузить) - такая позиция идёт в «проверить», вывозить её
  вручную; окно и «Проверки» показывают её отдельной строкой.
  Что обычно оставили бы - в последней колонке «По обычным правилам», в A3 красная пометка «ВЫВОЗ ВСЕГО». Оставить товар на
  месте = удалить строку в Excel и сохранить лист в «Корректировка_ЮА». Старый и новый ШК одного товара (barcode_recode_map) НЕ
  сливаются: на складе это две карточки, и каждая должна уехать под своим ШК.
  Контроль: в «Проверках» строка «<магазин>: ВЫЕДЕТ ВСЁ, КРОМЕ ПРИХОДОВ МАГАЗИНА - вывезти N поз. / X грн + остаётся M поз. / Y грн
  = остаток»; та же строка баннером в окне; при расхождении - ОШИБКА. Если у магазина нет ни приходов, ни остатка на ЮА
  (не на ЮА, нет файлов, режим без ЮА) - предупреждение, уезжает весь остаток. Папка результата обычная (ВЫВОЗ), а не «_зачистка».

РАСПРЕДЕЛЕНИЕ: ВЕСЬ ТОВАР НА МАГАЗИНЫ, ВКЛЮЧАЯ ТОВАР РЦ (галочка в шаге 2; в командной строке --rc-to-shops; 22.10.2026)
  Товар, который обычно идёт через РЦ, делится по точкам по спросу, как прямые поставки; файл на Полевая-Склад не создаётся
  (галочка «Сделать файл на Полевая-Склад» при этом отключается). Порог суммы на точку и «по точкам / по сумме / всё на один
  магазин» работают как обычно. Заменяет прежний «Довывоз» (его экран убран из окна); заморозка Бащинского из него - отдельная галочка ниже.

РАСПРЕДЕЛЕНИЕ: ЗАМОРОЗКА БАЩИНСКОГО ОДНОЙ ПАРТИЕЙ (галочка в шаге 2; в командной строке --bash-freeze; логика из довывоза, 22.10.2026)
  ШК заморозки Бащинского - из ВХОД_ВЫВОЗ\ДОВЫВОЗ\заморозка_бащинский.txt (нет файла - создаётся со списком по умолчанию, 14 ШК).
  Вся такая заморозка из списка едет ОДНОЙ партией на ОДНУ точку с его холодильником, без порога суммы и не на склад; остальной
  товар распределяется как обычно. Точка: выбрать из списка или «Найти по продажам» (за 60 дней продано не меньше 5 позиций этой
  заморозки не меньше чем в 6 неделях, лучшая - первая; можно задать список в холодильники_бащинский.txt). Не выбрана - расчёт
  возьмёт лучшую сам; не нашёл - заморозка делится по спросу, в итоге предупреждение. Выбор запоминается. Стаканы, кофе и пакеты
  этой галочкой не трогаются (они делятся как обычно).

СВЕРКА НАКЛАДНОЙ (раздел «Сверка накладной»; решение 28.10.2026)
  Когда: накладная перемещения в Торгсофте уже проведена, а часть товара физически осталась на магазине (её переводят на ЮА).
  Загрузите накладную (.xls или .xlsx Торгсофта: «Поставщик» / «Получатель», «Штрих код», «Кол-во»; строки сверяются с «Итого»,
  не сошлось - ошибка). У каждой строки галочка «Едет» (по умолчанию стоит) и «Факт» (по умолчанию как в накладной):
  уехало - оставить галочку, осталось на магазине - снять, количество другое - поправить «Факт» (0 снимает галочку).
  Пробел переключает выделенные строки; поиск по ШК или названию, Enter в поиске (сканер) переключает найденную строку.
  «Сформировать ТСД»: ВЫВОЗ\<сегодня>\<отправитель>\Сверка_накладной_<время>\<получатель>.txt (ШК;количество, cp1251, \r\n,
  одинаковые ШК складываются; после записи перечитан и сверен) + протокол Excel: Итог, Едет, Убрано - остаётся, Изменено количество.
  Дальше: удалить старую накладную в Торгсофте -> загрузить txt в ТСД и провести новую -> снять свежую выгрузку Family ->
  «Инвентаризация ЮА». Пока старая накладная проведена, убранного товара в остатке магазина нет.

ПРОПУСКИ ЮА (кнопка «Пропуски ЮА (Excel)» в шаге 2 «Списков вывоза»; в командной строке --missed-ua "Магазин"; 28.10.2026)
  Что закупщицы не поставили переводимому магазину на ЮА: товар есть на складе ЮА или на других точках ЮА (база ЮА, СКЛАД_ЮА,
  МАГАЗИНЫ_ЮА, приходы ЮА), а у этого магазина на ЮА нет ни прихода, ни строки в базе ЮА. Точка «Производство ЮА» не считается.
  Лист «Важно - у Фемели есть»: магазин этот товар держит (строка в его выгрузке Family, даже с нулём; по ШК, склейке
  barcode_recode_map, парам или тому же названию). Лист «Возможно» - остальное. Колонки: ШК ЮА, название, поставщик (последний
  приход поставщика ЮА, иначе матрица), остаток склада ЮА, на скольких точках ЮА есть остаток, где есть, ШК и остаток Фемели.
  Запускать в любой день, лучше до перевода, со свежими МАГАЗИНЫ, БАЗА_ЮА и ПРИХОДЫ_ЮА. Файл: ВЫВОЗ\<сегодня>\<магазин>\Пропуски_ЮА_*.xlsx.

УБРАНО ИЗ ОКНА (22.10.2026): экраны «Довывоз» и «Подчистка списка», режим «Зачистка остатка». Всё это делается на двух
  вкладках: «Списки вывоза» (галочка «Вывезти ВСЁ») и «Распределение» (галочка «Весь товар на магазины»). Ключи командной
  строки --sweep и --update остались, окно их не показывает.

ПРАВИЛА (что не вывозится)
  * Не вывозятся вовсе: сигареты («Сигарети…», «ТВЕН…»); они остаются на полке и идут в инвентаризацию.
    Если на ЮА та же сигарета записана латиницей и другим ШК, пара объединяется (в файл идёт ШК ЮА);
    неоднозначные пары (два одинаково подходящих ШК на ЮА) не объединяются - статус «неоднозначно».
  * Кулинария и выпечка («Випічка…», «Кулінарія…»): не вывозится и в инвентаризацию ЮА не включается.
  * Расходники (пакеты, стаканы, крышки и пляшки розлива, сырьё кофеаппарата, кеги, овощи) не вывозятся и когда
    они в матрице, а на ЮА их не было.
  * Штучный товар («... 1 шт»), у которого на ЮА есть та же упаковка под другим ШК («Упаковка 24 шт», «(100)»):
    не вывозится и в файл инвентаризации не включается (штука и упаковка - разные единицы), лист «Штучные -
    упаковка на ЮА». Пары находятся по названию и по таблице Справочник\vyvoz_shk_pairs.csv (ШК Family, ШК ЮА,
    комментарий; правится в Excel; там уже Троллі Глаз = Глотзер, подтвердить).
  * Исключённые поставщики: см. ниже.
  * Один товар под разными ШК объединяется: по перекодировке (старый + новый ШК в магазине - одна строка),
    по названию с матрицей и ЮА; одинаковые ШК файла инвентаризации сливаются.
  * Если вне матрицы больше 40% позиций магазина, это ОШИБКА сопоставления: txt не пишется.

ПОСТАВЩИКИ ДЛЯ ВЫВОЗА (исключить / вернуть)

  вывозятся. Если файла нет, он создаётся со списком по умолчанию: УДК, Хладік, Хладопром, Прем*єр Фуд,
  Фаст Фуд, Овочі-Фрукти (Протопопов), ФОП Протопопов. Исключённый поставщик: его товар остаётся на полке и идёт в

  Как менять:

  действует (там правила Справочник\vyvoz_perishable.csv).

ВАЖНО
  * Приход «от инвентаризации» на склад ЮА в BigQuery сознательно не грузится (разовая постановка остатка).
  * Колонка «Поставщик»: матрица -> иначе последний приход в базе (BigQuery, окно 180 дней; колонка «Поставки за 120 дн.» - по-прежнему 120); если и там нет, пусто.
  * Количества по учёту Торгсофта. Физический остаток может отличаться. Выгрузки старше суток дают предупреждение;
    перед сбором выгрузите свежие остатки магазина и пересоберите список.
  * Выгрузки не перемещаются и не удаляются. Повторный запуск за ту же дату уносит в ВЫВОЗ\_замененные\ только папки пересчитываемых
    магазинов и прошлую сводку; папки других магазинов этой даты (их ТСД_по_адресам, Обновление_*, Инвентаризация_ЮА_*)
    остаются на месте (с 14.10.2026).

ПОРЯДОК РАБОТЫ С МАГАЗИНОМ (07-08.10.2026)
  1. Свежие выгрузки в ВХОД_ВЫВОЗ -> «Списки вывоза» -> «Сформировать». Печатать лист «Вывезти на склад».
  2. Лист можно ИСПРАВИТЬ в Excel (удалить строки, уменьшить количества). Сохраните исправленную копию в
     «Корректировка_ЮА». Если правок нет - во вкладке «Распределение» кнопка «Взять без правок» кладёт в «Корректировка_ЮА»
     копию листа «Вывезти на склад» (один лист, 7 колонок - как в исправленных листах; исходный список не меняется,
     чужой файл не затирается). Автоматический лист из ВЫВОЗ\... напрямую в распределение не идёт.
  3. «Распределение» берёт лист ТОЛЬКО из «Корректировка_ЮА» (выпадающий список, новые сверху; ~$ и «проверка» не
     показываются) и сразу пишет, чей это лист, на какую дату и сколько позиций. Нужен лист «Вывезти на склад» с
     «Вывоз вне матрицы: <магазин> -> ...» в A1 и колонками Штрих-код / Название товара / Количество.
     Результат: txt для ТСД по адресам (имя файла = адрес) + Распределение.xlsx.
     Позиции РЦ -> Полевая-Склад.txt (галочка в окне; --no-rc отключает), прямые поставки -> N точек (1-10) с наибольшим
     СПРОСОМ НА ЭТОТ СПИСОК (решение владельца 09.10.2026), кроме перешедших на ЮА (Справочник\vyvoz_ua_stores.csv) и
     закрытых. Спрос точки = сумма по ШК списка min(продажи за 60 дн. / 2, количество в списке) * себестоимость;
     меньше 2 чеков за 60 дн. - случайная продажа, не спрос (для весового и кегов фильтра нет). При равенстве - по обороту.
     ШК делится между выбранными точками по продажам ЭТОГО ШК; не продавался - по продажам его группы (первое слово
     названия); нет и их - по спросу точки на список; нет и его - по обороту. На точку не меньше 3 шт/кг, меньше - лидеру.
     В ОБОИХ режимах точка, которой досталось меньше 5000 грн, убирается, её товар делится между остальными.
     Остатки точек НЕ учитываются. В Распределение.xlsx: «Спрос на этот список» (Сводка), «Как делилось» (Маршрут).
     Маршрут позиции: список раскомплектации Справочник\vyvoz_razkompl.csv (Сервис -> «Раскомплектация: на точки»;
     поставщик, слово из названия или ШК -> всегда на точки при любом количестве: Монжар, Агропром, Мак Кофе, Джамп /
     Петрівська Слобода, решение 15.10.2026) > Справочник\vyvoz_route_suppliers.csv (поставщик -> РЦ или Точки) >
     последнее поступление на этот магазин (перемещение с Полевая-Склад = РЦ, приход поставщика = прямая) > последнее
     поступление по сети (с 15.10.2026: так же, позже - то и берётся; раньше любое старое перемещение с РЦ давало РЦ) >
     нет истории = РЦ.
     Кеги («Кег» в названии) на РЦ НЕ везутся никогда и ПО ЛИТРАМ НЕ ДЕЛЯТСЯ (решение 09.10.2026). Количество кега - в
     порциях 0,5 л, объём кега - в скобках названия: «0,5л (30)» = 30 л = 60 порций, «(50)» = 100 порций; без скобок -
     самый частый приход по всей сети за 90 дней. Позиция режется на целые кеги и начатый (135,8 = 60 + 60 + 15,8),
     каждый кусок целиком едет на одну выбранную точку, где этот ШК продаётся больше всего (можно все на одну);
     не продаётся - на точку с наибольшим спросом на список. Только выбранные точки, в обоих режимах.
     ВЕСЬ ВЫВОЗ НА ОДИН МАГАЗИН (с 14.10.2026; в окне поле «Весь вывоз на один магазин», в командной строке --to-shop "Магазин"):
     всё, что обычно делится по точкам (прямые поставки и кеги - целыми кегами), едет на выбранный магазин; товар РЦ - как обычно на Полевая-Склад
     (магазин должен работать и не быть в списке ЮА, источник нельзя). Оценка считается по товару, который едет на магазин.
     В Распределение.xlsx: «Оценка продаж 60 дн» - сколько продано этого ШК там за 60 дней и сколько из отправленного продастся
     за 60 дней, если продажи будут такими же (остаток магазина не учитывается: актуальных данных нет); «Сравнение магазинов» -
     та же оценка по всем работающим точкам не на ЮА, лучший сверху. Итог (доля, место выбранного магазина, лучший) - в журнале.
  4. Следующий день: «Подчистка списка» убирает из исправленного листа и готовых txt то, что уже стало ЮА-шным:
     ШК есть в выгрузке Склад ЮА (с любым остатком, в т.ч. 0 и минус) либо, для прямой доставки, ШК есть в
     выгрузке этого магазина в базе ЮА. Исходные файлы не меняются; очищенные копии - в «Обновление_<дата>»
     (там ЧИТАЙ_МЕНЯ.txt): в ТСД берите файлы ОТТУДА. Итоги и нумерация очищенного листа пересчитываются.
     Что убрано и под каким ШК это на ЮА - Удалено_по_приходу.xlsx.
  5. Вывоз проведён -> снимите НОВУЮ выгрузку Family -> «Инвентаризация ЮА»: файл строится по факту остатка,
     а не по спискам: всё, что осталось на полке, кроме кулинарии и штучных. ШК ЮА подставляется там, где он найден
     (перекодировка, то же название, таблица пар). Результат: ВЫВОЗ\<дата>\<магазин>\Инвентаризация_ЮА_<время>\
     (txt для ЮА + xlsx: сверка и лист «Нет карточки на ЮА» - товар, которого ЮА не знает ни по ШК, ни по названию;
     для него в ЮА создастся новая карточка; это же рабочий список для таблицы соответствия ШК).
  6. Проверка, дошла ли инвентаризация: ЮА провела txt -> снимите выгрузку базы ЮА (все точки) в ВХОД_ВЫВОЗ\БАЗА_ЮА
     (или выгрузку магазина в МАГАЗИНЫ_ЮА) и свежую выгрузку Family -> «Инвентаризация ЮА» -> «Сверить с базой ЮА».
     По каждой строке txt (по умолчанию последнего; другой - «Выбрать txt…»): дошло / дошло, количество другое /
     не дошло (карточка на ЮА есть) / не дошло (карточки на ЮА нет) / не дошло, у Фемели уже 0. Плюс остаток Фемели,
     которого в txt не было, и что стоит на магазине ЮА сверх txt; по каждой позиции - где ещё она есть на ЮА.
     Результат: ВЫВОЗ\<сегодня>\<магазин>\Сверка_инв_ЮА_<время>\: xlsx и два txt для ЮА -
     «_доинвентаризация_ЮА.txt» (не дошло, карточка есть; количество - нынешний остаток Фемели, без выгрузки Family - из txt)
     и «_нет_карточки_ЮА.txt» (карточки на ЮА нет: сначала завести карточки). «Количество другое» в txt не идёт - решать вручную.
  Командная строка:
     --split "Корректировка_ЮА\<файл>.xlsx" [--top N] [--no-rc] [--day ГГГГ-ММ-ДД] [--shops "Магазин"]
     --update "Корректировка_ЮА\<файл>.xlsx" --state "<Склад ЮА>.xlsx" [--shop-ua "<магазин в базе ЮА>.xlsx"]
     --final-inventory "Магазин" [--final-file "<выгрузка Family>.xlsx"]
     --check-inv "Магазин" [--check-txt "<txt>;<txt>"] [--check-ua "<база ЮА>.xlsx"] [--check-fam "<выгрузка Family>.xlsx"]
  Имя папки магазина как в списках вывоза («/» в названии заменяется на «-»).

ЗАЧИСТКА ОСТАТКА (решение 08.10.2026)
  Когда остаток магазина нужно вывезти ЦЕЛИКОМ, независимо от матрицы и ЮА:
     python vyvoz_vne_matricy.py --sweep --shops "Качанівська 19" --auto-points
  (в окне: галочка «Зачистка остатка» в «Списках вывоза», затем «Распределение» с галочкой «Число точек по сумме»).
  Вывозится всё: в матрице и на ЮА, сигареты, алкоголь, кеги, штучные, исключённые поставщики, список «не вывозить».
  Остаётся на месте: кулинария, заморозка и скоропорты, расходники (пакеты, стаканы, крышки, розлив), сырьё
  кофеаппарата, овощи, позиции с ШК не из 6-14 цифр. Что именно остаётся - Справочник\vyvoz_perishable.csv
  (Тип: поставщик / название / ШК; «^слово» = название начинается со слова). Исключённое видно на листе
  «Исключено (не трогаем)». Кеги везутся только на РЦ.
  Результат лежит отдельно от обычного вывоза: ВЫВОЗ\<дата>_зачистка\<магазин>\ (там же ТСД_по_адресам).
  --auto-points: число точек считается по сумме прямых поставок, 5-7 тыс. грн на точку в среднем (из 10 первых по
  спросу); без него число точек задаёт --top N. Распределение по точкам неравномерное (доля по продажам ШК), это среднее.
  В обоих режимах точка, которой досталось меньше 5000 грн, убирается, а её товар делится между остальными (до тех
  пор, пока у всех не 5000+). Убранные точки и «точек было N, едет M» - в итоге распределения.
  Работает и для обычного списка: --split "<файл>" --auto-points.
  Свежую выгрузку Family нужно снять ПОСЛЕ проведения прошлого перемещения. Дата выгрузки берётся из имени файла
  (своя guess_day: номер дома в названии магазина не путается с датой).
