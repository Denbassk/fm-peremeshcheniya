Файл ведётся вручную патчами. Вставлять целиком в начало нового чата.

## Формула и округление
- IF(L<=0; (H+I)*1,2; IF(H>0; MAX((H+I)*1,2-L; 0); 0)), H=реализация, I=перемещение, L=на конец
- ROUND_MODE="up", WEIGHT_STEP=0.1, FIX_MIN_FRAC=0.34, MIN_Q_MIN_N=5, MIN_Q_MAX=100
- Весовой ящик: VES_BOX_MIN=1.5, VES_BOX_STOCK_MAX=1.0, VES_BOX_CRUMB=0.3
- Пакеты: BAG_BLOCK=50, всегда вверх. BLOCK_MIN_FILL=0.5

## Режимы
- Режим 1: обычный расчёт заказа РЦ -> магазины по потребности
- Режим 2: раздача с Полевая-Магазин по списку Вывоз_ДД.ММ.ГГГГ.xlsx, DIST_SHIP_ALL=True,
  сначала потребность, затем ВЕСЬ остаток пропорционально обороту точки, Полевая в ноль
- Режим 3 (ПЛАН, не реализован): перемещение неходового товара из магазинов-доноров

1. DIST_SHIP_ALL=True, правки в distribute_new и apply_dist_list - полный вывоз с Полевой
2. Исключения (кеги, кофе, розлив, овощи) защищены от полного вывоза

   Было: дробное qty при целом step уходило в int(round(q)) -> 0.175 в 0, 1.1 в 1,

## Решение по режиму 3 (принято)
- НЕ делать третий параллельный режим. Обобщить движок режима 2 до "донор -> получатели"
  с параметрами: доноры, получатели (свой список на донора), список ШК, ship_all, база
  пропорции. Режим 3 = вызов того же движка.
- Схема: через склад (пул на РЦ), не напрямую. Причина: рейсы только РЦ -> куст, прямого
  магазин -> магазин нет; пул по ШК даёт целые упаковки вместо крошек от каждого донора.
- Этапы: забор с доноров (txt на снятие) -> виртуальный пул по ШК -> раздача: сначала
  потребность по формуле, затем остаток пропорционально продажам ЭТИХ позиций у получателя
  (не общему обороту точки).
- Обязательные правила: не везти позицию в точку, где она тоже неходовая (матрица +
  продажи получателя); возврат донору запрещён; ship_all=False - нераспределённый
  остаток остаётся на доноре, в валидации строка "осталось у донора" как норма, не ошибка.
- Вход от пользователя: на донора - список неходовых ШК и список точек-получателей.
