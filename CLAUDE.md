# Family Market: расчёт заказа и перемещений

Контекст для Claude Code. Отвечай по-русски.

## Что здесь
- `РАСЧЕТ ЗАКАЗА/raschet_zakaza.py` (~3300 строк) - главный скрипт: расчёт заказа РЦ -> магазины
  из оборотной ведомости Торгсофт, раздача списка с Полевой, валидация. На Windows собирается
  в exe через `build_raschet.bat` (PyInstaller).
- `РАСЧЕТ ЗАКАЗА/_СОСТОЯНИЕ/СОСТОЯНИЕ_ПРОЕКТА.md` - режимы, сделанные правки, норма валидации,
  открытые хвосты, план режима 3. ЧИТАТЬ ПЕРЕД ЛЮБОЙ РАБОТОЙ.
- `РАСЧЕТ ЗАКАЗА/_СОСТОЯНИЕ/BQ_СХЕМА.md`, `BQ_СХЕМА_2.md`, `BQ_МАППИНГ.md` - схема BigQuery
  и ловушки сопоставления (имена магазинов, ведущие нули ШК, barcode_recode_map).
- `РАСЧЕТ ЗАКАЗА/_СОСТОЯНИЕ/ЖУРНАЛ.md` - журнал изменений.
- `РАСЧЕТ ЗАКАЗА/Справочник/transfer_pack.csv` - кэш справочника упаковок (офлайн-источник).
- `РАСЧЕТ ЗАКАЗА/_build/box_check.py` - вспомогательная проверка ящиков.
- `СИГАРЕТЫ/sigarety_tsd.py` - отдельный скрипт для ТСД по сигаретам.
- `ДОКУМЕНТЫ/` - спецификации логистических атрибутов, SQL, выгрузки кандидатов.

## Окружение облачной сессии
- Linux. Нет Windows, нет GUI (tkinter), нет доступа к BigQuery, нет реальных ведомостей.
- Запуск только без окон и без BQ: USE_GUI=False или аргумент --auto, REF_OFFLINE=True.
  В коммитах эти значения НЕ менять: пользователь работает на Windows с GUI и BigQuery.
  Переопределяй их в тестах или через переменные окружения.
- Зависимости: `pip install -r requirements.txt`.
- Файлы .xlsx в репозиторий не попадают (.gitignore). Для проверок на данных собирай
  синтетическую ведомость прямо в тесте.

## Источник истины
- Код важнее документов. Пример: в СОСТОЯНИЕ_ПРОЕКТА.md формула записана без -L, а в коде
  при NEG_AS_NEED=True минусовой остаток добавляется к потребности:
  IF(L<=0; (H+I)*1,2-L; IF(H>0; MAX((H+I)*1,2-L; 0); 0)).
  Нашёл расхождение документа с кодом - сообщи в отчёте.

## Правила работы
- Сначала отчёт, потом правки. Правки точечные, без рефакторинга "заодно".
- Одна правка - один PR с описанием на русском: что было, что стало, как проверено.
  Где возможно, добавляй контрольный случай в self_test().
- Не ломать Windows и PyInstaller: пути через os.path, txt для ТСД в cp1251 с \r\n.
- В write_shop_txt не удалять константу TXT_LINE_RE: её использует verify_written.
- Резервные копии файлов не создавать: история хранится в git.
- Пункты из раздела "Норма валидации" в СОСТОЯНИЕ_ПРОЕКТА.md не чинить.
- Бизнес-правила не выдумывать. Если правило неясно, задай вопрос в отчёте.
